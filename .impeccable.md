## Design Context

### Users

The product serves three audiences: demo users paper-trading BTC/ETH, technical reviewers inspecting
architecture and correctness, and developers running the full stack locally. Users are likely
evaluating trust, system state, and engineering depth more than brand personality.

### Brand Personality

Serious, precise, transparent. The interface should feel like an operational trading console: calm,
high-signal, and explicit about what is real, simulated, implemented, or still locked behind future
invariants.

### Aesthetic Direction

Use a dark, high-contrast console for trading and system panels, with amber for paper/demo state,
emerald for healthy or bid states, and red for ask/risk states. Avoid casino-like crypto visuals,
neon hype, glitch effects, gradient-heavy marketing sections, and anything that implies real-money
exchange readiness.

### Design Principles

- Start with the usable dashboard, not a landing page.
- Label fixture data and incomplete trading actions clearly.
- Keep market, order, portfolio, and system status scannable at desktop and mobile widths.
- Pair color with text or icons so trading state is not color-only.
- Prefer dense, stable modules over decorative cards.
